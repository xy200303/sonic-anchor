# UI/UX 设计方案

> 产品定位：桌面专业工具（直播导播台 + AI 运营助手），目标用户是**不懂直播的店家**——所以视觉要专业（像 OBS/直播伴侣），但交互必须比 OBS 简单一个量级。

## 1. 设计语言

**风格：专业暗色控制台（Dark Control Room）+ 玻璃拟态点缀**

- 直播软件的行业惯例是暗色（OBS、直播伴侣、vMix 都是），长时间盯屏不刺眼，且让"直播状态色"（开播红、警告黄、正常绿）在暗底上更醒目。
- 反模式规避：不做花哨的渐变插画风、不混用拟物与扁平、不用 emoji 当图标（统一 Lucide SVG 图标）。
- 支持亮色主题，但暗色为默认；两套主题用同一套语义 token 驱动，不允许组件里写死 hex。

## 2. 设计 Token

### 色彩（语义 token，暗色主题值）

| Token | 值 | 用途 |
|-------|-----|------|
| `bg-base` | `#141311` | 应用底色（暖调炭灰） |
| `bg-surface` | `#1C1B18` | 卡片/面板 |
| `bg-elevated` | `#24221D` | 弹窗、浮层 |
| `border-subtle` | `#34312A` | 分割线、卡片描边 |
| `text-primary` | `#EDEAE2` | 主文字（对比度 ≥ 4.5:1） |
| `text-secondary` | `#A8A29A` | 次要文字（对比度 ≥ 3:1） |
| `brand` | `#C4703F`（赭陶色） | 品牌主色——去 AI 味：不用蓝紫渐变，单一低饱和暖色点缀 |
| `live-red` | `#E23E32` | 开播中、录制中 |
| `success` | `#6FA287`（灰绿） | 正常、回复成功 |
| `warning` | `#D9A441` | 限频、队列积压 |
| `danger` | `#E03131` | 错误、危险操作 |

规则：功能色必须配图标或文字（不能只用颜色区分评论意图）；危险操作（停播、删除音色）用 danger 色且与普通按钮空间上隔离。

### 字体与排版

| 项 | 规范 |
|----|------|
| 字体 | 中文：系统栈（PingFang / Microsoft YaHei）；数字与英文：Inter |
| 字阶 | 12 / 13 / 14 / 16 / 18 / 24 / 32 |
| 正文 | 14px，行高 1.6 |
| 数据/计时/电平 | 等宽数字（`font-variant-numeric: tabular-nums`），防止跳动 |
| 标题字重 | 600–700；正文 400；标签 500 |

### 间距与圆角

- 4px 基准栅格：组件内距 8/12，卡片内边距 16，区块间距 24，页面边距 24/32。
- 圆角：按钮/输入框 6px，卡片 10px，弹窗 12px。
- 阴影：固定三级（卡片无阴影靠描边、浮层一级、弹窗二级），不随机取值。

## 3. 整体布局

```
┌────────────────────────────────────────────────────────────┐
│ 标题栏（自定义 frameless）：产品名 · 直播间状态胶囊 · 窗口控制 │
├──────────┬─────────────────────────────────────────────────┤
│          │                                                 │
│  侧边导航  │              主内容区（路由切换）                 │
│  200px   │                                                 │
│          │                                                 │
│  ·直播控制台★                                                │
│  ·话术脚本                                                   │
│  ·评论与回复              状态栏（全局，常驻底部）：             │
│  ·音色库              推流状态│评论连接│LLM│TTS│队列│电平      │
│  ·商品知识库                                                 │
│  ·数据中心                                                   │
│  ─────                                                     │
│  ·设置                                                       │
└──────────┴─────────────────────────────────────────────────┘
```

- 导航项 ≤ 7 个，图标+文字标签（不做纯图标导航），当前项高亮（品牌色指示条 + 背景提亮）。
- 危险/低频项（设置）与主功能分区隔开。
- 窗口最小 1280×800，默认 1440×900；面板可拖拽分栏但不做自由浮动窗口（控制复杂度）。

## 4. 核心页面：直播控制台（首页）

三栏式，信息密度按"直播中一眼可读"设计：

```
┌─────────────────┬──────────────────────┬──────────────────┐
│  画面预览         │  实时评论流            │  AI 回复队列       │
│  (OBS 场景/素材)  │  ·按意图着色标签        │  ·待播报列表        │
│  16:9 或 9:16    │  ·虚拟滚动             │  ·每条可:跳过/编辑/  │
│                  │  ·可点"手动回复"        │    立即播报         │
├─────────────────┤                      ├──────────────────┤
│  话术进度         │  快捷操作:            │  音频电平          │
│  段落时间轴+当前高亮│  [接管说话][插话]      │  TTS / BGM / 总线   │
│                  │  [静音 AI][紧急停止]   │  ducking 状态      │
└─────────────────┴──────────────────────┴──────────────────┘
```

关键交互规则：
- **每屏一个主 CTA**：未开播时主按钮是"开始直播"（brand 色大按钮）；开播后让位给"接管说话"，"停止直播"降级为次要且需二次确认。
- 评论流用**虚拟滚动**（一场直播可能上万条），新评论进入时列表平滑下移，用户上翻阅读时暂停自动滚动并显示"回到底部"浮钮。
- 意图分类用"图标+标签+色点"三要素，不用纯颜色区分。
- AI 回复进入队列先**预合成语音**（显示合成中 spinner），轮到播报时高亮 + 进度条；任何一条都可被人工跳过——**自动化的每一步都必须可人工否决**，这是半无人直播的信任基础。
- 紧急停止按钮常驻、danger 色、点击即停 AI 播报（不弹确认——逃生通道要快）；但"停止直播"弹确认对话框。

## 5. 其他页面要点

| 页面 | 布局与要点 |
|------|-----------|
| 话术脚本 | 左：商品选择；右：生成的话术分段卡片（可编辑/重生成单段/试听）。生成用骨架屏 + 流式打字效果，每段显示预估时长与累计时长 |
| 评论与回复 | 历史回放：按场次的评论列表 + 回复记录 + 筛选（意图/是否已回复）；支持把高频问题一键"加入知识库" |
| 音色库 | 音色卡片网格：波形缩略 + 试听按钮 + 来源标签（克隆/预设）。克隆入口是多步向导（见交互流程文档） |
| 商品知识库 | 商品列表 + 详情表单（卖点/价格/FAQ）；FAQ 用可展开的行内编辑；价格字段标记"AI 强制引用"徽标 |
| 数据中心 | 场次维度：评论数、回复率、平均响应延迟、互动趋势折线图 + 意图分布条形图（不用饼图超过 5 类）；图表配图例和 tooltip，空数据给引导文案 |
| 设置 | 分组表单：抖音账号/推流、LLM（Key、模型选择）、TTS（在线/本地切换 + 硬件检测结果）、音频（ducking 参数）、存储。API Key 用密码框 + 显示切换 |

## 6. 通用交互规范

- **反馈时效**：点击 100ms 内给视觉反馈；操作 >300ms 显示 loading；>1s 用骨架屏；异步按钮期间禁用防重复提交。
- **表单**：可见 label（不用纯占位符）；失焦校验，错误提示在字段下方并说明"怎么改"；多步流程有步骤指示器且可回退；长表单自动保存草稿。
- **弹窗**：模态必须有明确关闭入口；有未保存修改时关闭需确认；危险操作二次确认（删除音色、停播）。
- **Toast**：3–5 秒自动消失，成功/失败配图标；错误信息必须带恢复路径（"重试"按钮或"去设置检查 Key"链接）。
- **动画**：微交互 150–300ms，ease-out 进入 / ease-in 退出；只动画 transform/opacity；路由切换用 150ms 淡入；列表项入场交错 30ms；尊重 `prefers-reduced-motion`。
- **空状态**：每个列表/图表都有空态（插画 + 一句话引导 + 主操作按钮），不允许白屏。
- **可访问性**：对比度达标（正文 4.5:1）、完整键盘导航、焦点环可见、图标按钮带 aria-label、错误用 role="alert"。

## 7. 组件库落地

- **Naive UI**（推荐）：暗色主题开箱即用、TS 类型好、虚拟滚动/数据表格齐全；用其 `themeOverrides` 注入上面的 token。
- 图标：`lucide-vue-next`，统一 16/20/24 三档、stroke 2px。
- 图表：ECharts（vue-echarts），统一暗色主题配置。
- 自定义组件重点开发：`LiveStatusBadge`（状态胶囊）、`CommentItem`（意图标签）、`ReplyQueueItem`（带进度）、`AudioMeter`（电平条，Canvas 绘制）、`ScriptSegmentCard`（话术段）、`VoiceCard`（音色卡）。
