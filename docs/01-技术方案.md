# AI 直播助手 — 技术方案

> 技术栈：Electron + Vue 3 + TypeScript + electron-vite
> 目标：面向不会直播的企业/店家，提供"AI 语音讲解 + 评论自动回复 + 一键推流到抖音"的桌面软件

---

## 1. 总体架构

```
┌────────────────────────────── Electron 主进程 (Node.js) ──────────────────────────────┐
│  窗口管理 │ 推流引擎(FFmpeg/obs-websocket) │ 评论网关(WebSocket) │ LLM 编排 │ TTS 调度  │
│  SQLite 存储 │ 音频混流/ducking │ 话术调度器 │ 本地推理 Sidecar 进程管理 (Python)        │
└───────────────────────────────────────▲───────────────────────────────────────────────┘
                                        │ IPC (类型化 channel + 事件推送)
┌───────────────────────────────────────┴───────────────────────────────────────────────┐
│                          Electron 渲染进程 (Vue 3 + Pinia)                             │
│   直播控制台 │ 话术脚本 │ 评论与回复 │ 音色库 │ 商品知识库 │ 数据中心 │ 设置              │
└────────────────────────────────────────────────────────────────────────────────────────┘
                                        │
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
  抖音直播伴侣 / RTMP            抖音开放平台评论 API            云端 LLM / TTS API
  (推流地址 + 直播码)            (企业资质 / WebSocket)          (豆包 / DeepSeek / 火山语音)
```

**核心设计决策：不在 Electron 内自研音视频编码器。** 混流合成交给 FFmpeg（轻量方案）或 OBS（重方案），Electron 只做"编排和控制"。这是自研混流最容易翻车的点。

## 2. 进程模型与职责划分

| 进程 | 职责 | 关键技术 |
|------|------|---------|
| Main（主进程） | 推流控制、评论网关、LLM 编排、TTS 调度、音频混流、数据存储、Sidecar 管理 | Node.js |
| Renderer（渲染进程） | 全部 UI，无 Node 权限（contextIsolation 开启） | Vue 3 + Pinia |
| Sidecar：TTS 推理服务（可选） | 本地 CosyVoice2 / GPT-SoVITS 推理，HTTP/WebSocket 接口 | Python + FastAPI，打包为独立目录，首次运行按需下载 |
| Sidecar：FFmpeg | 音视频混流、编码、RTMP 推流 | ffmpeg-static 或随包分发 |

渲染进程通过 `contextBridge` 暴露的类型化 API 访问能力，禁用 `nodeIntegration`。

## 3. 模块设计

### 3.1 推流合成模块（两条路线，先做 A 后做 B）

**路线 A（MVP，推荐）：OBS 编排模式**
- 引导用户安装 OBS（或随包静默部署便携版），软件通过 **obs-websocket v5**（`obs-websocket-js`）全权控制 OBS：
  - 自动创建场景：摄像头源 / 素材视频源 / 图片轮播源
  - 自动创建音频源：TTS 音频（虚拟声卡或 OBS 音频源插件）、BGM（循环播放、音量闪避）
  - 通过 WebSocket 实时调音量、切换场景、启停推流
- 推流地址来自用户在抖音直播伴侣获取的推流码，软件填入 OBS 的推流配置
- 优势：混流、编码、推流的稳定性由 OBS 保证，开发量集中在编排

**路线 B（进阶）：内嵌 FFmpeg 直推**
- `ffmpeg-static` + fluent-ffmpeg：
  - 视频：抓摄像头（dshow）或循环素材文件
  - 音频：TTS PCM 流 + BGM 文件，`sidechaincompress` 滤镜实现 ducking（说话时 BGM 自动压低）
  - 输出 FLV → RTMP 推到抖音
- 优势：无需装 OBS，体验一体化；代价：要自己处理音视频同步、断流重连、码率控制

**ducking 参数建议**：阈值 -30dB、压缩比 8:1、attack 50ms / release 800ms，话术播完 BGM 平滑回升。

### 3.2 评论监控模块

- **合规路径**：抖音开放平台 → 企业开发者认证 → 直播能力/小玩法权限。通过直播伴侣获取 token，服务端换取直播间信息，WebSocket 长连接接收评论/礼物/进场事件。access_token 有效期 2 小时，需自动刷新。
- 架构：Electron 主进程内建 **评论网关服务**，本地起一个 WebSocket Server 中转，或直接在主进程维持长连接，事件通过 IPC 推给渲染层。
- 评论先落库（SQLite），再进入回复管线——保证断线重启后数据不丢、可追溯。
- ⚠️ 风险提示：抓包/逆向协议的方式不稳定且有封号风险，商用版本不采用。

### 3.3 LLM 编排模块

```
评论事件 → [预处理] → [意图分类] → [路由] ──命中问答──→ [RAG 检索商品知识] → [生成回复]
              │            │                                  │
              │            └─ 闲聊/喝彩 ──→ 模板化寒暄回复      └─→ 写入知识库命中日志
              │            └─ 无意义刷屏 ──→ 丢弃
              └─ 去重（相似问题缓存答案）+ 限频（同人/同题冷却）
```

- **LLM 选型**：云端 API 为主（豆包 / DeepSeek / 通义千问，按成本选），本地小模型不现实（店家电脑无 GPU）。
- **商品知识库**：店家录入商品资料（卖点、价格、规格、FAQ），SQLite + FTS5 全文检索做轻量 RAG；进阶可加 embedding 向量检索。
- **Prompt 结构**：人设（音色对应的店家人设）+ 当前讲解段落上下文 + 商品资料 + 评论内容 → 输出 JSON `{ reply_text, speak: bool, priority }`。
- **双通道回复**：`reply_text` 走开放平台接口发文字评论；`speak=true` 时进入 TTS 语音插播队列。
- **安全护栏**：输出过敏感词过滤、价格类答案强制从知识库取数（防 LLM 编造价格）。

### 3.4 TTS 调度模块

- 统一抽象接口 `TTSProvider`（详见《02-TTS选型调研》），实现在线/本地可切换：
  ```ts
  interface TTSProvider {
    synthesize(text: string, voice: VoiceProfile, opts): Promise<AudioResult>   // 离线预合成
    stream(text: AsyncIterable<string>, voice: VoiceProfile): AsyncIterable<PCMChunk> // 流式
    listVoices(): Promise<VoiceProfile[]>
  }
  ```
- **话术预合成**：开播前将整场脚本分段合成缓存为音频文件，开播即播，零延迟。
- **实时回复合成**：LLM 流式输出 → 按标点切句 → 流式 TTS → 边合成边送入混流，目标端到端延迟 < 3s。
- **插播队列**：优先级队列（人工插话 > 高优先评论回复 > 常规回复 > 话术轮播），支持打断与恢复。

### 3.5 话术引擎

- LLM 根据商品资料生成结构化脚本：`开场 → 卖点讲解段 × N（循环）→ 催单段 → 结束语`，每段带建议时长。
- 调度器按时间轴轮播讲解段，实时回复插播后自动回到断点续播。
- 支持"半无人模式"：真人可随时点"接管"说话，AI 静音让路；松开后 AI 继续。

### 3.6 数据存储

| 数据 | 方案 |
|------|------|
| 配置、话术库、音色元数据、评论记录、知识库 | SQLite（better-sqlite3，WAL 模式） |
| 音频缓存（预合成话术） | 文件系统 `userData/audio-cache/`，LRU 清理 |
| 音色模型文件（本地 TTS 时） | `userData/voices/` |
| 敏感凭证（API Key、token） | Electron `safeStorage` 加密后落盘 |

## 4. 工程结构

```
douyin/
├── electron.vite.config.ts
├── src/
│   ├── main/                    # 主进程
│   │   ├── index.ts
│   │   ├── modules/
│   │   │   ├── stream/          # 推流（OBS 控制 / FFmpeg）
│   │   │   ├── comment/         # 评论网关（抖音开放平台）
│   │   │   ├── llm/             # LLM 编排、意图分类、RAG
│   │   │   ├── tts/             # TTSProvider 抽象 + 火山/CosyVoice 实现
│   │   │   ├── script/          # 话术引擎与调度器
│   │   │   ├── audio/           # 混流、ducking、插播队列
│   │   │   └── store/           # SQLite、safeStorage
│   │   └── ipc/                 # 类型化 IPC 注册
│   ├── preload/index.ts         # contextBridge API
│   ├── renderer/                # Vue 3
│   │   ├── src/views/           # 控制台/话术/评论/音色/知识库/数据/设置
│   │   ├── src/stores/          # Pinia
│   │   └── src/components/
│   └── shared/                  # 主/渲染共享类型与 IPC channel 定义
├── sidecar/
│   └── tts-server/              # Python CosyVoice2 服务（可选下载）
└── docs/
```

## 5. 关键依赖

| 用途 | 选型 |
|------|------|
| 脚手架 / 构建 | electron-vite |
| UI 框架 | Vue 3 + `<script setup>` + TS |
| 组件库 | Naive UI（暗色主题友好、TS 支持好）或 Element Plus |
| 状态 | Pinia |
| OBS 控制 | obs-websocket-js v5 |
| FFmpeg | ffmpeg-static + fluent-ffmpeg |
| 数据库 | better-sqlite3（FTS5 做知识库检索） |
| 评论长连接 | ws |
| 图标 | lucide-vue-next（不用 emoji 当图标） |

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 抖音评论/回复接口需要企业资质 | 提前申请开放平台认证；MVP 期用"只读监控 + 人工半自动回复"降级 |
| 平台打击纯无人直播 | 产品定位"AI 辅助 + 真人随时接管"的半无人模式；保留真人介入的强交互入口 |
| 店家电脑配置低 | TTS 默认走在线 API；本地 TTS 作为可选项，启动时检测 GPU 才开放 |
| 断流/断网 | 推流层自动重连 + 状态上报；评论网关断线重连 + 评论落库补偿 |
| LLM 编造价格/承诺 | 价格类回答强制查知识库，不交给模型自由生成 |
