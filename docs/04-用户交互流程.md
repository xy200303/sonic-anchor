# 用户交互流程与实现方案

> 覆盖从首次安装到直播复盘的全流程。每个流程给出：步骤、界面状态、异常分支、前后端实现要点。

## 0. 全局状态机（直播会话）

```
idle ──配置完成──▶ ready ──点击开播──▶ starting ──推流成功──▶ live
                                      │                     │
                                      └─失败──▶ error ◀──断流─┤
                                                              ├─▶ paused（真人接管中）
                                                              └─用户停止──▶ ending ──▶ ended（复盘）
```

渲染层用一个 Pinia store（`useLiveStore`）持有会话状态，主进程是唯一状态源，通过 IPC 事件 `live:state-changed` 推送——**UI 不自行推断状态**，避免两端不一致。

## 1. 首次启动与初始化向导（Onboarding）

**目标：让完全不懂技术的店家 15 分钟内配置完能开播。**

| 步骤 | 界面 | 关键交互 | 实现要点 |
|------|------|---------|---------|
| 1. 欢迎 | 品牌页 + "开始配置" | 单按钮，无歧义 | 检测是否首次启动（SQLite 无配置记录） |
| 2. 抖音接入 | 二选一卡片：A. 填推流码（直播伴侣获取，图文教程+视频链接）B. 开放平台授权（企业资质用户） | 主推 A，B 标记"推荐，功能更全" | 推流码格式校验；授权走 OAuth，token 用 safeStorage 加密落盘 |
| 3. LLM 配置 | 模型供应商下拉 + API Key 输入 + "测试连接"按钮 | 测试按钮有 loading，成功打勾，失败给排错链接 | 主进程调各厂商 `/models` 或试算接口验证 Key |
| 4. TTS 配置 | 单选卡：在线（火山，填 Key）/ 本地（自动检测结果：GPU 型号、显存，达标才可勾） | 不达标显示原因 + "仍然使用在线"回退 | 启动时主进程执行硬件探测脚本，缓存结果 |
| 5. 完成 | 成功页 + "去克隆我的声音" / "先随便看看" | 允许跳过（用预设音色） | 写入配置，跳转控制台 |

异常分支：任一步骤可"暂时跳过"（除推流码外都有默认值），但控制台顶部常驻"配置不完整"警示条，点击跳回对应步骤。

## 2. 声音克隆向导

```
上传/录制样本 → 授权确认 → 试听参考音 → 提交克隆 → 进度 → 试听对比 → 命名入库
```

1. **样本采集**：两选一——上传音频文件（拖放区，支持 wav/mp3，自动校验时长 5s–5min、采样率）/ 软件内录音（调用麦克风，实时电平 + "环境太吵"提示）。
2. **授权确认**：强制勾选"我是声音本人或已获授权"（合规底线，记录授权时间戳与样本哈希入库）。
3. **克隆执行**：在线走火山克隆接口（秒级）；本地走 CosyVoice2。显示进度条 + 预计时间，可后台进行（toast 通知完成）。
4. **试听对比**：左原声右克隆，AB 切换播放同一段示例文案；不满意可"重新采样"。
5. **入库**：命名 + 标签（男声/亲和/促销感…），进入音色库。

## 3. 开播准备流程（核心路径）

```
选择商品(可多选) → 生成话术 → 审阅/编辑 → 选音色+BGM → 预合成 → 开播检查单 → 开始直播
```

| 步骤 | 交互细节 | 实现要点 |
|------|---------|---------|
| 选商品 | 商品卡片多选，显示已录资料完整度（缺 FAQ 给黄色提示"AI 回答质量可能受影响"） | 商品资料 → 拼装 LLM prompt 上下文 |
| 生成话术 | 点"AI 生成"→ 骨架屏 → 流式输出分段卡片；每段可：编辑文字 / 单段重生成 / 试听 / 调整顺序(拖拽) / 删除；顶部显示总时长 | LLM 流式接口，按段落标记切分；话术存 SQLite 支持多版本 |
| 音色+BGM | 音色卡片选择 + 语速滑杆(实时试听)；BGM 从内置库/本地文件选，音量滑杆 + ducking 预览开关 | 试听走预合成缓存，同一文本不重复调 API |
| 预合成 | 点"预合成全场话术"→ 分段进度条，失败段可单独重试 | 并发 2–3 路合成，结果写 `audio-cache/`，清单入库 |
| 检查单 | 自动检测清单：推流码✓ OBS/FFmpeg✓ LLM✓ TTS✓ 麦克风/摄像头✓ 网络✓；全部绿色才可点"开始直播"（也可强制跳过非关键项） | 每项检测是主进程独立 probe，并行执行，3s 内出结果 |

## 4. 直播中交互（最重要）

### 4.1 评论自动回复回路

```
评论到达 ──▶ 控制台评论流出现(意图标签) ──▶ AI 判定
   ├─ 刷屏/无意义 ──▶ 灰色折叠，不进队列
   ├─ 闲聊 ──▶ 模板回复(仅文字)，队列不播报
   └─ 有效问题 ──▶ 生成回复 ──▶ 进入回复队列(状态: 合成中→待播报→播报中→已完成)
                                      │
                              人工可随时: 跳过 / 编辑文字 / 置顶立即播报
```

- **评论流**：虚拟滚动；意图标签（提问/价格/售后/闲聊）图标+文字+色点；点击任意评论 → 右侧弹出"手动回复"输入框（语音播报 or 仅文字）。
- **回复队列**：每条显示 评论摘要 → AI 回复文案 → 语音合成进度 → 播报进度条。队列积压 >5 条时顶部 warning 提示并自动开启"合并同类问题"模式。
- **限频可视化**：同一用户被限频时，该评论标记沙漏图标 + tooltip"该用户回复冷却中（30s）"。

### 4.2 真人接管（半无人核心）

- **接管说话**：按住（或点按锁定）大按钮 → AI 播报立即淡出（300ms）→ BGM 保持 → 状态变 `paused` → 松开/解锁后 AI 从断点继续。
- **插话**：输入文字 → 立即合成并插入队列头部播报（如"欢迎刚进直播间的朋友"）。
- **静音 AI**：AI 只发文字回复不发声，话术轮播暂停——适合真人全程讲、AI 当助手。
- **紧急停止**：红色常驻按钮，一键停掉所有 AI 音频与队列，**无确认弹窗**（逃生通道）；但直播推流不断，真人说"稍等"即可。

### 4.3 异常处理

| 异常 | UI 表现 | 系统行为 |
|------|--------|---------|
| 推流断开 | 状态栏红色 + 全屏横幅 + 声音提醒 | 自动重连（指数退避，最多 5 次），重连期间话术暂停 |
| 评论连接断开 | 评论流顶部黄色条"评论接收中断，重连中" | 长连接重连；恢复后提示"中断期间可能有评论遗漏" |
| LLM 超时/失败 | 回复队列该条标记失败 + 重试按钮 | 自动降级：用 FAQ 模板回复，连续失败 3 次暂停自动回复并告警 |
| TTS 失败 | 合成中状态转红 | 自动切换备用 provider（本地→在线），toast 告知 |
| API 额度不足 | 设置页 + 控制台双提醒 | 检测到余额错误码即提醒，引导充值或切本地 |

## 5. 直播结束与复盘

1. 点"停止直播"→ 确认对话框（显示本场时长、评论数）→ 推流停止、话术停止。
2. 自动进入**复盘页**：场次概览卡（时长/评论数/回复率/平均响应延迟/预估互动提升）→ 互动趋势图 → 高频问题 TOP10（一键"加入知识库"）→ 未回复问题列表（标记原因：限频/分类丢弃/失败）→ 导出 CSV。
3. 复盘页 CTA："优化知识库"（跳到知识库并预填高频问题）——**让每一场直播训练下一场**，这是产品的留存钩子。

## 6. IPC 接口设计（流程 ↔ 实现对照）

| IPC channel | 方向 | 用途 |
|-------------|------|------|
| `config:get/set` | invoke | 配置读写（Key 加密） |
| `probe:all` | invoke | 开播检查单并行探测 |
| `voice:clone / voice:list / voice:preview` | invoke | 音色克隆与试听 |
| `script:generate`（流式）| invoke + 事件 `script:chunk` | 话术生成 |
| `tts:presynthesize` + 事件 `tts:progress` | invoke + push | 预合成进度 |
| `live:start / live:stop / live:takeover` | invoke | 会话控制 |
| `live:state-changed` | push | 全局状态机 |
| `comment:new` / `comment:batch` | push | 评论流（批量节流推送，防 UI 卡） |
| `reply:queue-changed` | push | 回复队列快照 |
| `reply:skip / reply:edit / reply:priority` | invoke | 人工干预 |
| `alert:critical` | push | 断流等关键告警 |
| `stats:session` | invoke | 复盘数据 |

规则：高频事件（评论、电平）批量 + 节流推送（100ms 窗口）；状态类事件全量快照推送（队列整体替换），避免增量同步的复杂度。

## 7. 开发里程碑建议

| 阶段 | 范围 | 验收标准 |
|------|------|---------|
| M1 骨架（2 周） | electron-vite 工程、导航布局、设计 token、配置与设置页 | 能跑通 Onboarding 并保存配置 |
| M2 推流（3 周） | OBS 编排、摄像头+素材场景、BGM+ducking、开播检查单 | 手动点击能把画面+音乐推到抖音 |
| M3 AI 讲解（3 周） | 话术生成、音色克隆（在线 TTS）、预合成、话术轮播 | 无人值守播完整场话术 |
| M4 评论闭环（3 周） | 评论监控、意图分类、回复队列、真人接管 | 评论 → 语音回复端到端 < 5s |
| M5 打磨（2 周） | 复盘报表、异常降级、本地 TTS 可选包 | 断网/断流演示全部有兜底表现 |
